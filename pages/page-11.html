Lesson 11

Hash Tables

"A hash table maps keys to values using a hash function — turning any key into an array index for near-instant O(1) average lookup."

What is a Hash Table?

A hash table stores key-value pairs. When you write a value, a hash function converts the key into a number — that number becomes the index in an underlying array where the value is stored. When you read it back, the same function runs again and jumps straight to that slot. No scanning, no searching.

Analogy

Think of a coat check at a venue. You hand in your coat (the value) and receive a numbered ticket (the hash). To retrieve your coat, you don't search every rack — you hand back the ticket and go straight to slot #3. A hash table does exactly this, instantly, every time.

Collisions & Chaining

Two different keys can produce the same bucket index — this is a collision. The most common fix is chaining: each bucket holds a linked list of all entries that hashed there. A good hash function distributes keys evenly so chains stay short — ideally length 1.

Watch out

A poor hash function that clusters all keys into a few buckets degrades performance from O(1) to O(n) — as bad as a plain array scan. V8 (JavaScript's engine) detects degenerate access patterns and switches internal representation strategies automatically.

Common Operations

JavaScript 
// Map is the preferred hash table in JS
const map = new Map();

// O(1) avg — set a key-value pair
map.set('name', 'Amara');
map.set('age', 24);

// O(1) avg — retrieve by key
const name = map.get('name');     // 'Amara'

// O(1) avg — check existence
map.has('age');                   // true

// O(1) avg — delete a key
map.delete('age');

// O(n) — iterate all entries
for (const [key, val] of map) {
  console.log(key, val);
}
TypeScript 
const map = new Map<string, string | number>();

map.set('name', 'Amara');
map.set('age', 24);

// Type-safe retrieval (may be undefined)
const name: string | number | undefined = map.get('name');

// Typed iteration
for (const [key, val] of map.entries()) {
  console.log(`${key}: ${val}`);
}

// Plain object with index signature
const scores: Record<string, number> = {};
scores['Amara'] = 95;
scores['Bola']  = 88;
Python 
# Python's dict IS a hash table
scores = {}

# O(1) avg — set
scores['Amara'] = 95
scores['Bola']  = 88

# O(1) avg — get (with default)
val = scores.get('Kemi', 0)      # 0 if key missing

# O(1) avg — check existence
'Bola' in scores               # True

# O(1) avg — delete
del scores['Bola']

# O(n) — iterate
for key, val in scores.items():
    print(key, val)

# defaultdict — auto-initialises missing keys
from collections import defaultdict
freq = defaultdict(int)
for ch in 'banana':
    freq[ch] += 1               # {'b':1,'a':3,'n':2}

Where Hash Tables Show Up

JavaScript Objects

Every JS object is a hash table under the hood. Writing obj.name runs a hash lookup — O(1) property access is what makes dynamic languages usable at scale.

Database Hash Joins

PostgreSQL and MySQL build an in-memory hash table from the smaller table in a join. This turns a naïve O(n²) nested loop into an O(n) operation for large datasets.

DNS Caching

Your browser stores domain→IP mappings in a hash table. Before making any network request, it checks this cache — turning a 50ms DNS lookup into a nanosecond O(1) hit.

Password Hashing

bcrypt and Argon2 apply a one-way hash function to passwords before storing them. The stored hash can't be reversed — authentication is O(1) compare, no plaintext ever saved.
