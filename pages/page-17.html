Lesson 17

Sorting Algorithms

"Sorting rearranges a collection into a defined order — the choice of algorithm determines whether this costs O(n log n) or O(n²), a difference that compounds massively at scale."

The Simple Sorts — O(n²)

Three elementary algorithms — bubble, selection, and insertion sort — all run in O(n²) and share one thing: they work by repeatedly comparing adjacent pairs or scanning for the next minimum. Easy to understand, correct, and completely impractical for large inputs. At n=10,000, they do 100 million comparisons; merge sort does roughly 130,000.

Insight

Insertion sort is the exception: on nearly-sorted data it runs in O(n) — it only shifts elements that are out of place. This is why V8 uses insertion sort for arrays shorter than ~64 elements, and Timsort (Python/Java's built-in) uses it for small runs within a larger merge-sort pass.

Merge Sort — O(n log n) guaranteed

Merge sort follows divide and conquer: split the array in half recursively until each piece has one element (trivially sorted), then merge pairs back together in sorted order. It takes O(log n) splits and O(n) work at each merge level, giving O(n log n) always — no worst case degradation. The cost: O(n) extra memory for the merge step.

Quick Sort — O(n log n) average

Quick sort picks a pivot element and partitions the array: everything smaller than the pivot goes left, everything larger goes right. Then it recursively sorts each side. In-place and cache-friendly, it outperforms merge sort in practice on random data — but degrades to O(n²) if the pivot is always the worst choice (e.g. smallest or largest element on a sorted array).

Watch out

Quick sort degrades to O(n²) when the pivot is always the minimum or maximum — which happens on already-sorted input with a naïve "pick last element" pivot. The fix: random pivot selection or the median-of-three strategy. Most production implementations use this.

Merge Sort & Quick Sort

JavaScript 
// Merge Sort — O(n log n) guaranteed, O(n) space
function mergeSort(arr) {
  if (arr.length <= 1) return arr;
  const mid   = Math.floor(arr.length / 2);
  const left  = mergeSort(arr.slice(0, mid));
  const right = mergeSort(arr.slice(mid));
  return merge(left, right);
}

function merge(left, right) {
  const out = [];
  let i = 0, j = 0;
  while (i < left.length && j < right.length)
    out.push(left[i] <= right[j] ? left[i++] : right[j++]);
  return [...out, ...left.slice(i), ...right.slice(j)];
}

// Quick Sort — O(n log n) avg, O(n²) worst, O(1) extra space
function quickSort(arr, lo = 0, hi = arr.length - 1) {
  if (lo >= hi) return arr;
  const p = partition(arr, lo, hi);
  quickSort(arr, lo, p - 1);
  quickSort(arr, p + 1, hi);
  return arr;
}

function partition(arr, lo, hi) {
  const pivot = arr[hi];
  let i = lo - 1;
  for (let j = lo; j < hi; j++) {
    if (arr[j] <= pivot)
      [arr[++i], arr[j]] = [arr[j], arr[i]];
  }
  [arr[i + 1], arr[hi]] = [arr[hi], arr[i + 1]];
  return i + 1;
}

def _merge(left, right):
    out, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            out.append(left[i]); i += 1
        else:
            out.append(right[j]); j += 1
    return out + left[i:] + right[j:]

Where Sorting Shows Up

Database ORDER BY

Every SQL ORDER BY triggers a sort. PostgreSQL uses quicksort for in-memory sorts and merge sort for external (disk-based) sorts — chosen depending on whether the data fits in RAM.

Search Result Ranking

Google ranks billions of pages by relevance score on every query. Sorting by score runs on distributed hardware — even a 1% speedup in the sort saves thousands of CPU-hours per day.

JavaScript & Python Built-ins

V8's Array.prototype.sort() uses Timsort (merge + insertion hybrid). Python's list.sort() also uses Timsort — O(n) on already-sorted data, O(n log n) otherwise. Always use built-ins.

Rendering Z-index

The browser's compositor sorts DOM elements by z-index to determine paint order. On every reflow, a stable sort preserves the relative order of elements at the same z-level.
